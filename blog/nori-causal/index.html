Introducing Nori-Causal: From What Matters to What Causes

Glass-box models show which features Nori relies on. Nori-Causal goes one step further: it tells you which features drive the target, and which are driven by it.

#Causal Discovery#Tabular Data#Foundation Models#Explainability
In short

A predictive model tells you which features matter, but not why. A feature can matter because it drives the target or because it is driven by it, and only the first kind is something you can act on. Nori-Causal reads a table and, in a single forward pass, returns the probability that each feature is a cause or an effect of the target. It learns this from the same synthetic tables that Nori is pretrained on, where the true causes and effects are known.

In our glass-box post, we showed how Nori can be distilled into simple, interpretable relationships between the target and the features: one readable curve per feature that you can check and defend. Now, we push this intuition forward with Nori-Causal, which shows what the causes and the effects of the target are.

The Problem

A glass-box model answers an important question: which features does the prediction depend on, and how? But a feature can be predictive for two very different reasons. It can drive the target, or it can be driven by it.

Consider credit default. Missed payments are a strong signal of an upcoming default. So are collection calls. Any predictive model, glass box or not, will rate both as important. But only one of them is a lever. Fewer missed payments lower the risk of default. Stopping the collection calls does not, because the calls are a consequence of the risk, not its source.

Almost every decision built on top of a model is an intervention: approve a loan, change a treatment, adjust a price. Before acting, we need to know which features are causes of the target and which are effects of it.

Fundamental Issues

Telling causes from effects using only a table is hard, for three reasons.

  • Correlation has no direction. Accuracy and feature importance are symmetric. A feature that causes the target and a feature caused by the target can look identical to a predictive model.
  • Real data has no answer key. Real tables never come with their true causal graph. The experiments that would reveal it are often slow, expensive, or unethical, so there is little to learn from or check against.
  • There are too many possible graphs. Classical causal discovery searches over graphs, one dataset at a time. With 5 features there are already 29,281 possible graphs, and with 10 there are about 4 × 1018. Most methods also rely on strong assumptions about the data.

Our Solution: Nori-Causal

Nori-Causal addresses these issues with the same recipe that makes Nori work: learn from synthetic data where the answer is known, then apply what was learned to real tables without any retraining.

How does Nori-Causal work?

Nori-Causal takes a table and a target column. In a single forward pass, it returns two probabilities for every feature: the probability that the feature is a cause of the target, and the probability that it is an effect of the target. A feature for which both are low is neither.

Like Nori, it is never trained on your data. There is no graph search and no tuning. The table is the only input.

How do we train it?

Nori is pretrained entirely on synthetic tables, many of which are generated from a random causal graph: a few columns are sampled first, and every other column is computed from its parents through random functions and noise. For Nori, the graph is only a means to an end. It produces realistic tables, and once a table is made, the graph is thrown away.

For Nori-Causal, we keep the graph. Because we generated the data ourselves, we know exactly which columns caused the target and which were caused by it. This gives us what real data never has, an answer key, and we train Nori-Causal to recover it from the table alone.

Every training table comes from a different graph, with different functions, noise levels, and sizes. To do well across all of them, Nori-Causal cannot memorize any single dataset. It has to learn the general patterns in the data that reveal which way the arrows point. That is what lets it read a real table it has never seen.

Summary

Feature importance tells you what a prediction depends on. Glass-box models show you how. Nori-Causal adds the direction: which features drive the target, and which are driven by it. It learns this from synthetic tables whose causes and effects are known, and it needs nothing but your table at inference time.
